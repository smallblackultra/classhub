# 部署与运维手册

> 目标：把 `class-deadline-hub` 从「本机 `python -m app`」变成「班委和同学都能打开的网址」。
> 本项目只有一个进程、每个班一个 SQLite（新闻缓存在 `portal.db`）、零第三方依赖，运维成本刻意压到了最低。
> **当前实际线上部署**（2026-11-10，含 8 个班库、登录、DDL、新闻抓取）见 [`09-远程完整DDL与新闻抓取.md`](09-远程完整DDL与新闻抓取.md)；本文是通用手册。

---

## 1. 运行环境

| 项 | 要求 |
| --- | --- |
| Python | 3.10+（开发验证于 3.12）。**不需要 pip 安装任何包** |
| 磁盘 | 代码 < 1 MB；数据库按班级规模，通常 < 50 MB |
| 内存 | 30–80 MB |
| 端口 | 默认 8000（`--port` 可改） |
| 系统 | Windows / Linux / macOS 均可 |

可选：`Node.js` 仅用于开发时给前端脚本做语法检查，运行站点**不需要** Node。

## 2. 本机试跑

```bash
cd class-deadline-hub
python -m app --reset --port 8000
# 打开 http://127.0.0.1:8000
```

演示账号见 README。正式使用前必须 `--reset` 后重新建班级（见 §4）。

## 3. 局域网试用（不暴露公网）

```bash
python -m app --host 0.0.0.0 --port 8000
```

- 同学用 `http://<你的内网 IP>:8000` 访问。
- Windows 需放行防火墙入站 8000/TCP：
  `New-NetFirewallRule -DisplayName "ClassHub 8000" -Direction Inbound -Protocol TCP -LocalPort 8000 -Action Allow`
- 注意：**http 下 Cookie 不带 Secure**，只适合校内局域网短期试用。

## 4. 正式部署（公网 / 校内域名 + HTTPS）

### 4.1 首次初始化

```bash
python -m app --db /srv/classhub/data/classhub.db --port 8000
```

不要在正式库上使用 `--reset`（它会清空数据）。首次启动会自动建表。
然后用管理员账号登录，按「管理 → 成员」审批成员、轮换邀请码；管理员默认口令务必第一时间修改（见 §7）。

### 4.2 systemd（Linux）

`/etc/systemd/system/classhub.service`：

```ini
[Unit]
Description=ClassHub 班级截止日
After=network.target

[Service]
Type=simple
WorkingDirectory=/srv/classhub
Environment=CDH_ENV=prod
Environment=CDH_NOTIFY_INTERVAL=60
# 可选：AI
# Environment=DEEPSEEK_API_KEY=sk-xxxx
ExecStart=/usr/bin/python3 -m app --host 127.0.0.1 --port 8000 --db /srv/classhub/data/classhub.db
Restart=always
RestartSec=3
User=classhub
Group=classhub

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now classhub
journalctl -u classhub -f          # 看日志（访问日志也写到 stderr）
```

`CDH_ENV=prod` 会让会话 Cookie 带 `Secure`，**必须配合 HTTPS**，否则浏览器不会保存登录态。

### 4.3 Windows 常驻

任选其一：
- 用 [NSSM](https://nssm.cc/) 把 `python -m app --host 127.0.0.1 --port 8000` 注册为服务；
- 或计划任务「登录时运行」，命令填 `pythonw.exe -m app ...`（`pythonw` 无控制台窗口）。

### 4.4 Nginx 反代 + HTTPS

```nginx
server {
    listen 80;
    server_name deadline.example.edu.cn;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    server_name deadline.example.edu.cn;

    ssl_certificate     /etc/letsencrypt/live/deadline.example.edu.cn/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/deadline.example.edu.cn/privkey.pem;

    client_max_body_size 2m;

    location / {
        proxy_pass         http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header   Host              $host;
        proxy_set_header   X-Real-IP         $remote_addr;
        proxy_set_header   X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header   X-Forwarded-Proto $scheme;
        proxy_read_timeout 60s;
    }
}
```

证书：`certbot --nginx -d deadline.example.edu.cn`。Caddy 更简单，一行 `reverse_proxy 127.0.0.1:8000` 即可自动 HTTPS。

> 站点必须是**单一域名**：Cookie 为 `SameSite=Lax`，登录态不会跨域携带。

### 4.5 健康检查与监控

```bash
curl -fsS http://127.0.0.1:8000/api/health
# {"ok":true,"version":"0.1.0","db":true}
```

把这条命令挂到 Uptime Kuma / 云监控的 HTTP 探活即可；连续失败 3 次告警。

## 5. 备份与恢复

### 5.1 自动备份（推荐每天）

```bash
cd /srv/classhub
python -m app --backup                     # 每个班库 + portal.db 各写一份 <slug>-YYYYmmdd-HHMMSS.db
python -m app --backup --backup-out /srv/backup
```

- 使用 SQLite 在线备份 API，**服务运行中也可执行**，不锁库。
- 默认保留最近 14 份（`CDH_BACKUP_KEEP`，0 = 不清理）。
- 恢复时会用到 `data/.secret`（密码加密密钥），它**不在**数据库里，迁移/备份时要一起保留。
- 管理端「报表 → 备份数据库」也能即时下载一份（仅管理员）。

cron 示例：

```cron
15 3 * * * cd /srv/classhub && /usr/bin/python3 -m app --backup >> /var/log/classhub-backup.log 2>&1
```

### 5.2 恢复

```bash
systemctl stop classhub
# 把备份文件放回对应位置：data/classes/<slug>/classhub.db、data/portal.db
# 并保留 data/.secret 及其 0600 权限
systemctl start classhub
```

恢复前先确认备份文件完整：

```bash
python -c "import sqlite3;print(sqlite3.connect('备份文件').execute('PRAGMA integrity_check').fetchone())"
```

### 5.3 迁移到新机器

1. 拷贝整个 `class-deadline-hub/`（含 `data/classhub.db`，以及可选 `data/backup/`）；
2. 新机器装 Python 3.10+；
3. `python -m app` 启动即可。没有其他状态（无 Redis、无消息队列、无上传目录）。

## 6. QQ 群机器人部署

链路：QQ 群 → NapCat（OneBot v11）→ `bot/onebot_bridge.py` → ClassHub。

### 6.1 准备

1. 管理端「接入 → 数据源」新建 `QQ 机器人`，复制一次性令牌 `qq_<班级ID>_<32位>`（只显示一次，丢了就重建）。
2. 一台**保持在线**的机器（校内服务器 / 云主机 / 常开 PC）安装 NapCat，登录一个 QQ 小号并拉进班群。
3. 启动桥接：

```bash
export CLASSHUB_URL=http://127.0.0.1:8000
export CLASSHUB_TOKEN=qq_1_xxxxxxxxxxxxxxxx
export ONEBOT_URL=http://127.0.0.1:3000
export ONEBOT_SELF_ID=机器人QQ号
export BOT_WEBHOOK_SECRET=$(head -c 24 /dev/urandom | base64)   # 可选，防伪造上报
python bot/onebot_bridge.py
```

4. NapCat 后台把「HTTP 上报」指向 `http://127.0.0.1:8790/onebot`，消息格式选 array 或 string 均可。
5. 群里 `@机器人` 发通知验证；机器人会回「已记下…，等班委确认」。

### 6.2 安全

- 令牌只存在桥接进程的环境变量里；泄露后立即在管理端重建数据源。
- 桥接只监听 `127.0.0.1`，不对公网开放。
- 设置了 `BOT_WEBHOOK_SECRET` 时，NapCat 上报需带同名头（部分版本在 WebUI 配置）。
- 机器人只处理**被 @** 的消息，且只产草稿，不会直接发布。

### 6.3 排错

| 现象 | 排查 |
| --- | --- |
| 群里 @ 没反应 | 桥接日志有没有收到事件；NapCat 上报地址/端口；`ONEBOT_SELF_ID` 是否机器人 QQ |
| 桥接 401 | `CLASSHUB_TOKEN` 与数据源令牌不一致，或数据源被禁用 |
| 消息进了「未解析队列」 | 正常：原文没识别出截止时间，班委手动补录或重试 |
| 机器人回复失败 | `ONEBOT_URL` 不通；未配置时只在日志打印，不影响入列 |

## 7. 安全清单（上线前逐项确认）

- [ ] 修改管理员默认口令；演示账号全部删除或停用（`--reset` 只用于演示库）。
- [ ] `CDH_ENV=prod` + HTTPS，确认浏览器里 Cookie 带 `Secure`。
- [ ] 邀请码只发给本班，注册后必须班委审批；泄露后立刻「轮换邀请码」。
- [ ] 防火墙只暴露 80/443；8000 与 8790 只监听回环地址。
- [ ] 备份文件与数据库同等敏感（含学号姓名），权限 600，异地留存一份。
- [ ] AI Key 只放服务端环境变量，不进代码库、不写进前端。
- [ ] 站内只存完成状态（完成/不适用），不存作业内容；如学校有额外隐私要求，按需删减字段。
- [ ] 定期 `PRAGMA integrity_check`（或直接校验最新备份）。

## 8. 升级

1. 先 `python -m app --backup`；
2. 替换代码目录（保留 `data/`）；
3. 重启服务。启动时 `init_schema()` 会自动补齐新表/新列（幂等迁移），无需手工改库；
4. 打开 `/api/health` 与首页确认版本。

## 9. 常见问题

**Q：能不能不用命令行，双击启动？**
Windows 可建一个 `start.bat`：`@echo off` + `cd /d %~dp0` + `python -m app --open`。

**Q：多班级？**
数据模型已按 `class_id` 隔离，管理端一次管理一个班；多班部署建议每个班一个库文件 + 一个端口/子域名，或在后续版本加班级切换。

**Q：数据量大了会慢吗？**
单班 < 200 人、几千条 deadline，SQLite 足够；WAL 模式下读写不互相阻塞。

**Q：邮件/企业微信提醒？**
当前是站内通知（铃铛）+ 浏览器打开即见的完成率。邮件/企微推送需要额外 SMTP/应用凭证，作为后续扩展（`notifications.channel` 字段已预留）。
