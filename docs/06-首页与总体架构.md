## 2. 路由与入口

完整站只监听一个 origin（本机 `127.0.0.1:8000`，远端 `127.0.0.1:8000` 由 OpenResty 反代），用路径区分门户和 DDL。

| 请求 | 行为 | 实际文件/说明 |
| --- | --- | --- |
| `GET /` | 班级门户首页 | `web/home.html`（远端由 OpenResty 静态直出） |
| `GET /personalcenter/` | 独立个人中心 | `web/personalcenter/index.html` + `assets/personalcenter.js` |
| `GET /daliy/` | DDL 应用（规范路径） | `web/index.html` |
| `GET /daily/` | DDL 应用（兼容别名） | 同上 |
| `GET /daliy`、`/daily` | 302 到带斜杠路径，保留 query | `app/server.py` 前缀处理；远端 Nginx 精确 location |
| `GET /index.html` | 302 到 `/` | 防止旧外壳变成第二个 DDL 首页 |
| `GET /api/...` | API 始终在根路径 | `/daliy/api/...` 在服务端剥前缀后同样命中 |
| `GET /api/news` | 公开新闻 JSON | 新闻缓存，不要求登录 |
| 未知静态文件 | 有扩展名 → 404；无扩展名 → 对应入口的 SPA 回退 | 首页 `home.html`，DDL `index.html` |

实现位置：

- `app/config.py`：`APP_PREFIX="/daliy"`、`APP_ALIASES=("/daily",)`；远端 `CDH_BASE=/daliy`；
- `app/server.py`：`_serve_static()` 用 `home = "index.html" if is_app else "home.html"`；
- 门户用 hash 路由（`home.js`），DDL 用原有 `#/list` 等 hash 路由（`api.js`），互不干扰。

> 门户资源使用相对路径 `assets/...`，DDL 链接使用站点根绝对路径 `/daliy/`。当前部署在域名根路径；若整体挂到 `/class/`，应改成配置注入的 base。

## 4. 登录、会话与权限

### 4.1 门户不另建账号体系

1. 首页加载读取已有会话：`GET /api/auth/me`，只刷新右上姓名/头像；头像 chip 不绑定点击。
2. 点「个人中心」进入 `/personalcenter/`；未登录显示登录卡，登录成功留在该页。
3. 个人中心集中处理资料、头像、个人待办、班级工具、改密和退出；DDL 顶栏/底栏「个人中心」与旧 `#/profile` 路由都跳到这里。
4. 个人中心右上角「DDL 查询」默认不显示边框，鼠标移入/键盘聚焦时才出现金色描边；右上角校训标记取消旋转，保持水平对齐；个人待办日期框空值显示「年/月/日」，聚焦后再显示浏览器日期时间输入。

登录与资料由 `app/api/auth_api.py` 负责：

- `POST /api/auth/login`：学号 + 密码，成功后种 `cdh_sid`（HttpOnly）、`cdh_csrf`（前端可读）、`cdh_cls`（班级）；
- `GET /api/auth/me`：返回 `user / class / permissions / pending_drafts / unread_notifications / server_time`，其中 `user.avatar` 为 data URL 或空串；
- `POST /api/auth/avatar`：登录用户（含待改密）保存头像；只接受 PNG/JPEG/WebP data URL，长度上限 400,000 字符，空串表示清除；写审计；
- `POST /api/auth/change-password`：个人中心底部直接改密；`must_change_password` 用户会看到提醒，不再跳 DDL 安全页；
- 登录时若当前班库找不到学号，会遍历 8 个班库定位，所以远端不需要班级选择器。

DDL 登录页的 `nextPath()` 仍只接受同源、以 `/` 开头的站内路径，防开放重定向；门户自身不再使用该回跳。

### 4.2 权限边界

- **公开内容**：门户介绍、学院新闻标题/摘要、名言可匿名读；
- **班级数据**：DDL、归寝、报名、活动照片、课程资料必须走服务端会话 + 班级隔离；
- 新接口沿用 `@route(..., auth="required", committee=False)`；写操作要求 `X-CSRF`；
- 远端 `CDH_ENV=prod`，会话 Cookie 带 `Secure`，必须通过 HTTPS 域名访问。

## 5. 新闻资讯：已实现的抓取管线

### 5.1 来源与解析

| 栏目 | 列表页 | 说明 |
| --- | --- | --- |
| 通知公告 | <https://wdzxy.hfut.edu.cn/5630/list.htm> | 有 2021 年置顶项，必须按日期重排 |
| 我院新闻 | <https://wdzxy.hfut.edu.cn/5628/list.htm> | 活动/科研新闻 |

条目结构：

```html
<li class="news n1 clearfix">
  <a href="/2026/1110/c5630a324408/page.htm">
    <div class="date"><em>10</em><span>2026-11</span></div>
    <div class="txt"><h4>标题</h4><div class="desc">摘要</div></div>
  </a>
</li>
```

`app/news.py` 用标准库正则解析（不引入 HTML 解析依赖），并：

- 跳过无 `h4`/`href` 的占位条目；
- 解析 `2026-11-10` 或 `10 2026-11` 两类日期，按发布日期倒序；
- 用 `urljoin` 归一化链接，只允许 `wdzxy.hfut.edu.cn` 的 http(s)，统一升级 https；
- 标题/摘要去标签、去零宽字符、压空白，摘要限 220 字。

### 5.2 数据流

```text
启动 warmup / TTL 到期
  → fetch 两个栏目（12s 超时、2MB 上限、串行）
  → parse_list（标题、日期、摘要、URL 白名单）
  → portal.db: DELETE 本栏目 + INSERT 新列表（事务）
  → portal_news_meta: last_attempt / last_success / last_error
  → GET /api/news?limit=3
  → home.js initNews() 文本节点渲染
```

- TTL 默认 1800 秒；过期时先返回旧数据，后台单线程刷新（`_refresh_lock` 防重）。
- 无缓存时同步抓取一次；抓取失败保留旧数据。
- 单栏失败不影响另一栏；`error` 只记录，不抛 500。

### 5.3 表结构

```sql
CREATE TABLE portal_news (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  category TEXT NOT NULL,
  title TEXT NOT NULL,
  summary TEXT NOT NULL DEFAULT '',
  source_url TEXT NOT NULL,
  published_at TEXT NOT NULL,
  fetched_at TEXT NOT NULL,
  UNIQUE (category, source_url)
);
CREATE INDEX idx_portal_news_category
  ON portal_news(category, published_at DESC);

CREATE TABLE portal_news_meta (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL
);
```

新闻对所有班相同，放在全局 `data/portal.db`，不复制进 8 个班库。

### 5.4 接口

```http
GET /api/news?limit=3
200 {
  "enabled": true,
  "updated_at": "2026-11-10T07:16:00Z",
  "attempted_at": "2026-11-10T07:16:00Z",
  "stale": false,
  "error": "",
  "items": {
    "notice": [{"category": "notice", "title": "…", "summary": "…",
                "url": "https://wdzxy.hfut.edu.cn/…", "published_at": "2026-11-10"}],
    "news":   [{"category": "news", "title": "…", "summary": "…",
                "url": "https://wdzxy.hfut.edu.cn/…", "published_at": "2026-11-10"}]
  }
}
```

`limit` 服务端限制 1–6；首页固定 3 条。前端用 `textContent` 渲染标题/摘要/日期，链接只接受后端已白名单的 URL。

### 5.5 前端状态

- 面板不再显示「学院官网 · 每 30 分钟同步」「已同步/缓存」徽标，避免把运维状态暴露给访客；
- 加载中显示每栏「正在读取学院官网…」占位；
- 有数据时只显示每条发布日期、右侧「访问官网」链接和页脚更新时间；
- 旧缓存（`stale`）仍展示内容，页脚文案改为「上次更新 …」；数据层 `data-news-state` 保留给样式/排错，不输出可见徽标；
- 无数据/抓取失败：显示「学院官网暂时无法读取」+ 官网入口，不伪造新闻；
- 1440 两栏并排；620px 以下上下堆叠。

### 5.6 抓取约束

- 不用第三方库；单请求 12 秒超时，2 MB 上限，串行；
- 只抓公开列表，不登录、不绕过限制；
- 不转载正文，只展示标题、摘要和外链；
- 尊重学院官网条款；上线前确认公开抓取许可和频率；
- 官网改版会中断解析，需用固定 HTML 样本补测试后更新 `parse_list`。

部署、缓存刷新与排错详见 [`09-远程完整DDL与新闻抓取.md`](09-远程完整DDL与新闻抓取.md)。

## 6. 数据持久化与部署

### 6.1 现有原则

- **一班一库**：`data/classes/<slug>/classhub.db`，登录命中班级后切库；跨班不可见。
- **全局库**：`data/portal.db`，只存新闻缓存等跨班数据。
- **单进程 SQLite/WAL**：写操作串行；8 个班、8 班规模足够。
- **无 ORM**：SQL 集中在 `app/domain/*`，迁移通过 `init_schema` + `migrate_all_classes()`。
- **备份**：`python -m app --backup` 现在同时复制班库和 `portal.db`；远端另有每日 tar 归档。

### 6.2 新模块的归属

| 数据 | 归属 | 理由 |
| --- | --- | --- |
| 归寝记录、请假、晚归 | 班库，新增 `dorm_records` / `dorm_leaves` | 只属于一个班 |
| 活动、报名、候补、签到 | 班库，新增 `activities` / `activity_signups` | 班内活动 |
| 班级活动日历 | 班库（复用活动表） | 与活动报名同源 |
| 精彩瞬间/相册 | 班库存元数据；图片放 `data/uploads/<slug>/` | 数据库不存大 BLOB |
| 课程信息/课表 | 班库，新增 `courses` / `course_slots` | 班级课表不同 |
| 新闻资讯 | 全局库 `portal.db` | 所有班同一份 |
| 首页名言 | 前端静态数据 | 无用户数据 |

### 6.3 本地与远端

- **本机完整站**：`python -m app`，门户 + DDL 同源，共用登录和班库；仍在本机运行。
- **远端完整站**：1Panel OpenResty 静态根 + `/api/`、`/daliy/`、`/daily/` 反代到 systemd 管理的 Python `127.0.0.1:8000`；数据在 `/opt/classhub/data`。
- **远端备份**：`/opt/classhub/backup.sh` 每日 03:17 归档 `data/`（含 `.secret` 和 `portal.db`），保留 14 天。
- **QQ 机器人/AI**：远端未部署，仍只在本机；远端以 `--no-notify` 启动。

### 6.4 PWA 与离线（2026-11-11 新增）

- **根作用域**：`web/sw.js` 由三套页面共同注册为 `/sw.js`，scope `/`，缓存名 `classhub-shell-v28`；DDL 旧 `/daliy/sw.js` 注册已移除并自注销，避免嵌套作用域。
- **页面外壳**：SW 预缓存 `/`、`/personalcenter/`、`/daliy/` 及三套 CSS/JS、vendor、图标；`ignoreSearch:true`，版本查询变化不会导致缓存 miss；导航网络优先、失败回落到对应外壳；静态缓存优先；**不缓存 `/api/`**。
- **接口缓存**：`web/assets/offline.js` 包装 `fetch`，把成功 GET（`/api/auth/me`、`/api/meta`、`/api/deadlines*`、`/api/personal*`、`/api/news*`）按学号写入 `localStorage`（前缀 `cdh.offline.v1.`）；离线时返回缓存，`/api/auth/me` 用上次资料维持页面打开；退出登录清空。
- **离线个人待办**：本地新增/修改/删除先落到本地队列，联网后 `syncPersonal()` 依次 POST/PATCH/DELETE；本地项带 `client_key`，服务端 `personal_items.client_key` 唯一索引幂等去重；同步前先从队列移除，失败回滚。
- **离线降级**：页面显示固定条「离线模式 · 显示上次缓存的数据 / N 条计划待同步」；DDL 自身离线条存在时根提示自动隐藏，避免重叠；离线不能发布/修改班级 DDL、审批、改密或首次登录。
- **安装入口**：根清单 `scope:"/"`、`start_url:"/"`、快捷方式 `/daliy/#/list`、`/personalcenter/`；首页/个人中心/DDL 均引入 `offline.js` 与根 manifest。
- **原生包**：Android WebView APK（debug 签名）与 Electron/NSIS Windows 安装包（未签名）加载同一线上站点；详见 `10-App与离线使用.md`。

安装、屏幕适配与原生包构建步骤见 [`10-App与离线使用.md`](10-App与离线使用.md)。

## 7. 失败模式与降级

| 场景 | 首页表现 | 处理 |
| --- | --- | --- |
| 未登录 | 用户区「登录/访」，其余正常 | 点击「个人中心」进入 `/personalcenter/` 登录，不跳 DDL |
| `/api/auth/me` 401 | 视作游客，不弹错误 | `home.js` 静默处理 |
| 会话过期 | 个人中心回到登录卡 | 门户 API 401 时清空本地登录态；DDL 的 401 逻辑继续处理 |
| 头像过大/格式不支持 | 个人中心红字提示 | 前端先压 256px；后端 400,000 字符上限兜底 |
| DDL 服务故障 | 门户仍开；DDL 卡/API 报错 | 门户是静态，不依赖 API 首屏 |
| 新闻抓取失败 | 旧数据 + 「缓存/抓取失败」 | 不阻塞首页；日志与 `portal_news_meta.error` |
| 新闻无缓存 | 空栏目 + 官网入口 | 不伪造新闻 |
| JS 禁用 | 文案、卡片、页脚可读 | `<noscript>` 说明 |
| 移动端 | 单列卡片、新闻堆叠、头像入口 | 390px 已验证 |
| 离线/断网 | 已缓存页面可打开，顶部显示离线条；个人待办可本地增删改 | 根 SW v26 + `offline.js`；首次打开未缓存的页面会提示 |
| 离线待办同步 | 联网后自动合并；重复提交由 `client_key` 唯一索引去重 | 同步失败保留本地队列 |
| 旧链接 `/daily/...` | 302/兼容到 DDL | 长期保留别名 |
